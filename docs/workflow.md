# 工作流

## 1. 捕获（30 秒）

看到/想到/听到 → 丢 `01-inbox/`。

- 不追求格式。
- 一条一件事。
- 先写标题，正文可以空。
- 来源来不及查就写“待补”。

```markdown
---
title: 待整理：Caddy 证书
type: note
status: inbox
created: 2026-11-06
tags: [待整理]
---

# 待整理：Caddy 证书

听说 80 端口必须通。待验证。
```

## 2. 每日


## 3. 每周（20 分钟）

```text
[ ] 逐条看 inbox
[ ] 能合并的合并
[ ] 能归类的移到 02/03/04
[ ] 加 1–3 个链接
[ ] 补来源
[ ] 更新 00-index 的“最近更新”
[ ] 完成的项目标 done
```

判断：

| 问题 | 去哪 |
|---|---|
| 有截止日/产出？ | `02-projects/` |
| 长期责任？ | `03-areas/` |
| 主题资料？ | `04-resources/` |
| 完成/失效？ | `05-archive/` |
| 还是不知道？ | 留在 inbox，下周再说 |

## 5. 项目流程

### 5.1 建项目页

用 `_templates/project.md`：

- 目标
- 成功标准
- 现状
- 下一步
- 风险
- 相关链接

### 5.2 过程记录

- 会议 → `meeting` 笔记，链到项目。
- 决策 → `decision` 笔记，写“选了什么/为什么/怎么回滚”。
- 踩坑 → `note`，链到项目。

### 5.3 结束

- 标 `status: done`。
- 写 3 行复盘：做对/做错/下次。
- 移到 `05-archive/`。
- 项目页保留链接。

## 6. 会议流程

会前：

- 建 `meeting` 笔记，写议题。
- 链到项目。

会中：

- 只记结论/行动项，不逐字记。

会后：

- 结论 1–3 条。
- 行动项：谁/做什么/截止。
- 链到相关项目/决策。
- 24 小时内发出去。

## 7. 读书/论文流程

1. 建 `source` 笔记：标题/作者/DOI/URL。
2. 摘 3–5 句**原文**，标页码。
3. 写 3 条自己的话。
4. 写“能用到哪”。
5. 链到主题笔记/项目。

> 不要整篇复制。摘原文 + 自己的判断。

## 8. 决策流程

```markdown
# 决策：用 SQLite 还是 PostgreSQL

## 背景
## 选项
## 决定
## 理由
## 回滚条件
## 相关
```

关键：**写下什么情况下会推翻这个决定**。
