# 排错

## 1. `[[链接]]` 点不开

| 原因 | 处理 |
|---|---|
| 目标笔记不存在 | 新建，或改链接 |
| 文件名大小写不一致 | 统一小写 kebab-case |
| 用了路径而不是 stem | Obsidian 用 `[[文件名]]`，不是 `[[文件夹/文件]]` |
| 目标在排除目录 | 检查 Obsidian 设置 |
| 中文/空格 | 改用英文文件名 |

```bash
python scripts/check-links.py ~/my-vault
```

## 2. 断链报告

`check-links.py` 会列出：

- `[[不存在]]`；
- 相对 Markdown 链接指向不存在的文件。

处理：

- 新建目标；
- 改链接；
- 删除无效链接（先确认）。

## 3. 孤岛笔记

没有任何入链/出链。

处理：

- 从 `00-index` 或主题页加入链；
- 合并到相关笔记；
- 归档。

> 新库孤岛多是正常的，不用一次清完。

## 4. Obsidian 同步冲突

现象：

```text
note (conflict 2026-11-06).md
```

处理：

1. 打开两个版本对比。
2. 合并内容。
3. 删除冲突副本（确认后）。
4. 以后：同一时间只在一台设备编辑。

## 5. 中文乱码

- 文件用 UTF-8。
- Windows 记事本另存为 UTF-8。
- PowerShell 5.1 读 UTF-8 无 BOM 可能乱码；用 VS Code/Obsidian 看。
- 不要用 GBK 保存。

## 6. 库太大/卡

- 附件太多：移到 `_attachments`，压缩图片。
- 插件太多：禁用不用的。
- 单文件太大：拆分。
- 搜索慢：用 `rg` 命令行。

## 7. AI 改坏了

1. 不要保存/继续。
2. `git diff` 看改动。
3. `git checkout -- 文件` 恢复（已 commit 的）。
4. 没 Git → 从备份恢复。
5. 给 AI 加规则：追加优先、不改原文、先读后写。

## 8. Git 冲突

```bash
git status
git diff
# 手动合并
git add .
git commit
```

> 不要直接 `git checkout .` 除非确认丢弃本地改动。

## 9. 文件被误删

- 先看回收站。
- Git：`git log --diff-filter=D --name-only` 找删除记录。
- 备份恢复。
- 不要再往同一盘写大量数据。

## 10. 备份失败

| 原因 | 处理 |
|---|---|
| 目标盘没插 | 检查盘符 |
| 权限 | 用有权限的账号 |
| 路径太长 | 缩短路径/开长路径 |
| 磁盘满 | 清理/换盘 |
| 文件被占用 | 关 Obsidian 再试 |

## 11. 最小诊断

```text
1. 库路径：
2. Obsidian 版本：
3. 是否 Git：
4. check-links 输出：
5. 最近改了什么：
6. 备份在哪：
```

> 贴日志前删掉私人内容。

## 12. 恢复顺序

```text
1. 停编辑（关 Obsidian）
2. 备份当前坏状态（别覆盖）
3. 从 Git/备份恢复
4. 打开验证
5. 搜 3 篇 + 开 2 个附件
6. 记录原因
```
